INSTALL

claude plugin marketplace add leandrodalbo/claudio-plugin
claude plugin install claudio@claudio-plugin

Needs Claude Code, git and Python 3.11+. Then run /claudio:init in your project.

Who it's for

ClaudioXP is for software engineers who want AI's speed and keep responsibility for what they ship.

1

You need the fundamentals.

It guides an engineer; it does not stand in for one. If you can't judge a change, ClaudioXP can't help you.

2

Know your paradigm.

Object-oriented, functional or structured, and why.

3

You don't need to be an expert in the language.

Bring the engineering know-how, and ask Claude to explain the language as you go.

4

It is not for "vibe" coding.

Every cycle stops for your decision: the spec, the tests, the review, the commit.

How it works

Work moves in small cycles. Each phase lets Claude do one kind of work, and only you move on. Open a phase to see what it allows.

Once per plan

1 PLAN
Claude may
change only the plan and the config.
You decide
when the plan is right.

↻ Every cycle

  1. 2 SPECIFY
    Claude may
    read and ask questions. It changes nothing.
    You decide
    the behaviour, in one or two sentences.
  2. 3 RED
    Claude may
    write tests only, in the cycle's files.
    You decide
    when to move on. Your tests must fail (pass in a coverage cycle).
  3. 4 PROMPT
    Claude may
    suggest a file to follow. It changes nothing.
    You decide
    the pattern, or “no pattern”.
  4. 5 GREEN
    Claude may
    write code only. Tests are locked.
    You decide
    when to move on. Your tests must pass.
  5. 6 REVIEW
    Claude may
    read and comment. It changes nothing.
    You decide
    what to fix.
  6. 7 REFACTOR
    Claude may
    clean up the code. Tests stay locked.
    You decide
    when to move on. Tests must still pass.
  7. 8 COMMIT
    Claude may
    suggest the message. Git is read-only for Claude.
    You decide
    the commit. You make it.

Cycle types

Each cycle in the plan has a type. The type sets the route.

behaviour

The full loop. RED expects new tests that fail.

coverage

The full loop. RED expects tests for what already works, that pass.

refactor · documentation · setup · spike

No RED. Tests stay locked the whole cycle.

Only you can skip, and only REVIEW and REFACTOR.

All the rules: docs/phases.md

The craft inside

At every phase, Claude gets the craft experienced engineers use. Not as a tip in a prompt, but as rules it reads before it writes.

  • TDD · BDD · XP

    Test first, behaviour in plain words, small steps and fast feedback.

  • Clean Code

    Names that say what they do, short functions, code the next person can change.

  • Clean Architecture

    Business rules free of details. Dependencies point inward.

  • SOLID

    Five checks on coupling and cohesion, run on every change.

  • KISS · DRY · YAGNI

    The simplest thing that works, one source for each rule, nothing “for later”.

  • Design patterns

    Used when the problem asks for one, with the signs it's overkill.

  • Tests

    Tests that make change safe and can't go stale.

  • Safety

    Safe by default: inputs checked, nothing outside the project touched, no secrets.

Read when the work needs it

  • Efficiency: collections, loops in loops
  • System design: many services, scale, load
  • Production: builds, pipelines, containers
  • Data and networks: tables, queries, ports
  • Runtime: JVM, memory, threads

Your corrections become rules.

Correct Claude once, and it offers to write the rule down, with the date: in your project's CLAUDE.md, or in your own copy of the skill if you install from a clone. Rules that help everyone? Send them as an issue.

Where the value is

You keep the speed, and your judgement decides what ships. This is how ClaudioXP makes that hold.

  • Enforced, not suggested.

    Hooks block the wrong move before it happens: files outside the plan, tests outside RED, tests changed in GREEN or REFACTOR.

    What Claude sees

    Tests are locked in GREEN, and tests/test_order.py is a test file. Go back to RED to change a test.

  • Tests decide.

    RED, GREEN and REFACTOR end only when your test command gives the right result. Claude saying “done” is not enough.

  • You are the gate.

    Claude can't move the phase or write to git. The hooks stop it, so the plan, the spec, the review and the commit stay yours.

  • Small steps.

    One plan, one cycle, one change you can really read.

  • Decades of craft built in.

    The craft is there at every step, and your corrections become rules.

Guard rails, not a sandbox. Tests prove behaviour, not design, so REVIEW is still a person reading the change.
